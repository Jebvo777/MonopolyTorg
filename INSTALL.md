# Установка сайта торговой компании «Монополия»

Сборка содержит рабочий PHP-сайт, весь импортированный каталог, товарные изображения, тематические фотографии, локальные шрифты, логотип, favicon, административную панель и единый SQL создания и заполнения базы.

## Требования

PHP 8.2–8.4; MySQL 8.0+ или MariaDB 10.6+; расширения PDO MySQL, mbstring, DOM/XML, fileinfo и OpenSSL. Сборка не требует Composer, Node.js или внешних сервисов для показа страниц. Серверу PHP необходима запись в `storage/` и `public/assets/img/uploads/`, а также `public/assets/documents/` при загрузке документов через админку.

## Установка на Apache-хостинг

1. Распакуйте архив. Перенесите содержимое каталога `monopoly-site` на сервер.
2. Предпочтительно укажите `public/` корнем сайта в панели хостинга. Если изменить корень нельзя, загрузите все содержимое в корневой каталог домена: включенные корневой `index.php` и `.htaccess` перенаправят запросы в публичную часть и закроют служебные каталоги. Для этого нужен Apache с `mod_rewrite` и разрешенным чтением `.htaccess`.
3. Создайте БД и пользователя в панели хостинга. Имя БД и пользователь: `system404_monop`. Пароль подключения уже задан в `app/config.local.php` и указан в `ACCESS.txt`. Хост БД по умолчанию — `localhost`; при необходимости измените его в конфигурации.
4. Импортируйте `database/monopoly_install.sql` через phpMyAdmin или MySQL-клиент. Скрипт создает структуру и заполняет каталог, страницы, документы, настройки, медиатеку и администратора. Пользователь MySQL создается в панели хостинга; SQL не меняет учетные записи сервера.
5. Укажите действующий адрес сайта в `base_url` файла `app/config.local.php`. По умолчанию указан `https://www.monopoly-torg.ru`. Для установки в подкаталог задайте `base_path`, например `/monopoly`, и включите его в размещение сайта. `base_url` должен содержать только протокол и домен.
6. Откройте главную страницу, затем `/admin`. Данные первого входа указаны в `ACCESS.txt`. После установки измените пароль в «Мой пароль».
7. В «Настройки и главная» задайте почтовый транспорт. Получатель заявок уже установлен: `monopoly@list.ru`. По умолчанию используется `mail()` хостинга. Для SMTP необходимы параметры настроенного почтового ящика: сервер, порт, шифрование, логин, пароль и разрешенный адрес отправителя.
8. Настройте задания cron для повторной отправки уведомлений и очистки старой анонимной статистики.

Пример импорта через консоль:

```bash
mysql --default-character-set=utf8mb4 -u system404_monop -p system404_monop < database/monopoly_install.sql
```

Если база создана заранее и учетной записи запрещено выполнять `CREATE DATABASE`, удалите из SQL только строку `CREATE DATABASE IF NOT EXISTS ...`. Строка `USE system404_monop` должна остаться. Остальные команды выполняются без изменений.

Вместо MySQL-клиента можно запустить `php bin/install.php`. Повторная установка блокируется; `--force` предназначен для осознанной переинициализации после резервной копии. Импорт полного установочного SQL поверх действующей БД обновляет исходный контент — используйте его для первой установки.

## Nginx

Для Nginx устанавливайте корень в `public/`. Пример основных правил:

```nginx
root /path/to/monopoly-site/public;
index index.php;
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
location ~ \.php$ {
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
}
location ~ /\. {
    deny all;
}
client_max_body_size 16m;
```

Пути каталога и PHP-FPM заменяются на значения вашего сервера.

## Очередь почты и обслуживание

Рекомендуемые задания cron:

```cron
* * * * * /usr/bin/php /path/to/monopoly-site/bin/send-mail.php
15 3 * * * /usr/bin/php /path/to/monopoly-site/bin/maintenance.php
```

Новая заявка сначала сохраняется в БД. Сайт пробует отправить уведомление сразу; при ошибке письмо остается в очереди. Cron повторяет отправку до пяти попыток, а ручная кнопка в заявке позволяет повторить ее после исправления настроек. Вложения хранятся вне публичной части и скачиваются через авторизованную админку.

Почтовый транспорт должен быть настроен на конкретном хостинге. Уведомление со статусом «Отправлено» означает принятие письма почтовым сервером; доставка в папку входящих зависит от почтовой инфраструктуры.

Очистка обслуживания удаляет статистику посещений старше 12 месяцев и попытки входа старше семи дней. Срок хранения обращений определяется компанией; удаление обращения доступно администратору и удаляет приложенный файл.

## Резервные копии и редактирование

Регулярно сохраняйте дамп БД, `storage/specifications/` и загруженные файлы в `public/assets/`. После изменения текста, SEO, документов или каталога через админку страницы обновляются из БД. XML-карта формируется автоматически по опубликованным карточкам.

Руководство администратора: `docs/admin-guide.md`. Анализ старой копии: `docs/analysis.md`; карта разделов: `docs/sitemap.md`; полный реестр товаров: `docs/products.csv`; манифест импорта: `docs/manifest.json`.

В репозитории GitHub двоичные материалы представлены архивами в `asset-packs/`. После клонирования восстановите их командой `python3 tools/unpack_assets.py`. В установочном архиве все ресурсы уже разложены по рабочим каталогам; дополнительная распаковка не нужна.
